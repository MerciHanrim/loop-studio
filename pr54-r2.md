## Round 2 — four boundaries closed (`714a890`)

### 1. Pure `prepareTransition` vs id generation (§1)
- **`prepareTransition()` is now PURE** — no `set`, no id, no counter. Returns
  `PreparedResult { fromStep, expectedCommitEpoch, expectedSimulationRev,
  expectedSeed, toState, derived }`. **100 repeat calls are byte-identical**
  (unit test) and the store is untouched.
- **`armPrepared(result)`** is the one impure step: mints `transitionId`, marks
  it active, and — in dev — `deepFreeze`s the payload so the animation layer
  cannot mutate `toState` / `derived` (unit test: mutation throws,
  `Object.isFrozen` true). `commitPrepared` also copies every field by value
  into fresh objects.

### 2. Complete teardown after a stale settle (§2)
- **`settleActive`**: a non-`committed` result (`stale` / `already-settled`)
  now **stops the rAF loop and drops the run to `paused`** — Play does **not**
  auto-re-prepare on top of a stale state.
- **`discardTransition`** — called by `reset` / `restoreSnapshot` / the
  `simulationRev` subscription **before** the state swap — cancels the rAF,
  drops `prepared`, clears `activeTransitionId`. A graph edit cancels playback
  **immediately**, it does not wait for the next settle.
  **New E2E**: edit mid-transition ⇒ `transition` null + `stepIndex` 0 within a
  frame + no late commit for 800ms.

### 3. Committed-state / engine-input audit (§3)
- **`expectedSeed` added to the prepared payload + the CAS** — seed is a prepare
  input; `setSeed` already resets, but the CAS now catches a bare seed change
  too (isolated unit test bypasses `setSeed`'s reset).
- **New unit test enumerates** graph edit / undo / redo / import (`loadJSON`) /
  template swap (`loadGraph`) / `restoreSnapshot` / `setSeed` and asserts each:
  moves `commitEpoch` **or** `simulationRev`, **discards** the prepared
  transition (`activeTransitionId` null), and makes a late `commitPrepared`
  return `"stale"`. (No timeline scrubber exists today — a code note flags it
  for whenever one is added.)

### 4. Background / visibility E2E (§4)
`loop()` early-returns while `document.hidden`: no τ advance, no settle, no
prepare; the rAF stays armed to catch the un-hide. **New E2E** (`installHidden`
overrides `document.hidden`):
- hidden mid-transition ⇒ no commit, same `activeTransitionId` (no new
  transition prepared);
- visible + a big time jump ⇒ the current transition settles **exactly once**,
  the next begins a frame later, every step in `series` once;
- Paused + hidden/visible ⇒ **no auto-settle**;
- Reset then a visibility callback ⇒ **no late commit**.

Plus: `stepOnce` hardened against a stray armed id with no scheduler transition.
